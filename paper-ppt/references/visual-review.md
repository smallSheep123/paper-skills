# 视觉 AI 审阅协议

视觉模型不是最后一步“查有没有溢出”的工具，而是整个 PPT 工作流中的视觉编辑。

## 1. 什么才算视觉审阅

必须把**实际图片像素**交给具备视觉能力的模型/Agent。

以下都不算：

- 只读文件名；
- 只看图片尺寸；
- 只看 alt text；
- 只看 PPT/XML；
- 只读生成代码。

有独立视觉审阅 Agent 时优先使用；否则由多模态主 Agent 分阶段自审，并明确记录 `self-review`。

不要假定某个固定工具名一定存在，先使用宿主的工具发现机制确认实际能力。

## 2. 审阅输入

每次审阅尽量同时提供：

- 当前页面的真实渲染图；
- 必要时对应的原论文页面 / Figure；
- 本次 design brief；
- 这页要表达的 message；
- 需要核对的证据或风险。

设计意图只是背景，不是免检理由。

“这是故意留白”“这是学术风所以字小”都不能用来回避可读性问题。

## 3. 五个审阅阶段

### Source：原始证据

检查：

- Figure/Table 编号；
- 子图；
- caption；
- 坐标、单位；
- 图例；
- 指标方向；
- 裁切完整性。

公式页另外核对源 PDF 与 LaTeX 的数学含义，并查看分式、根号、上下标、求和范围、矩阵括号、分段条件、多行对齐和注释间距。原生公式的编辑性与显示须在目标 PowerPoint 检查；阅读器使用后备图时，不能把渲染成功写成原生公式已验证。实现与检查方法见 [math-equations.md](math-equations.md)。

同时回答：

- 这张图能支持什么结论？
- 不能支持什么结论？
- 哪些值看不清，不能猜？

### Design：视觉定调

如果用户提供了视觉参考，实际查看后提炼：

- 层级；
- 密度；
- 字号；
- 配色；
- 网格；
- 留白；
- 图文组织；
- 页面节奏。

只提炼语言，不照抄页面。

没有参考图时，直接评价当前样页，不声称看过不存在的素材。

### Pilot：代表性样页

重点看方法页和实验页：

- 能否沿页面讲清机制；
- 论文图是否过小；
- 图表条件是否充分；
- 阅读顺序是否自然；
- 是否出现“整齐但不好讲”的问题；
- 是否符合当前风格而不模板化。

### Slides：逐批页面

每批逐页看全尺寸渲染图。

检查：

- 内容是否忠实；
- 公式/图表是否完整；
- 字号、图例是否可读；
- 对齐与间距；
- 主视觉焦点；
- 术语与色彩一致性；
- 页面是否真的比论文原图更容易讲。
- 图片是否等比，方形图中的圆点、字形和网格是否变形；
- 标题、主图和强调数字是否支持同一个结论；
- 图之间的连接表达的是原有关系还是额外推断；
- 核心正文是否被缩成脚注，以及重要限制是否离结果太远。

修复后必须重新渲染，再看修改后的页面。

### Deck：整套终审

最终同时查看：

1. 所有全尺寸页面；
2. contact sheet / 缩略图总览。

确认：

- 逐页问题已经解决；
- 页面密度没有突然失控；
- 方法与实验页没有退化为截图堆积；
- 风格统一但不机械；
- 页面之间有清楚节奏。

多风格对比时另看**跨风格总览**（行 = 风格，列 = 页型）：逐列判断是否有超过三分之一的风格共用同一骨架；各风格同一页是否讲同一份内容。不满足即记为 high 问题。

缩略图不能替代全尺寸审阅。

## 4. 问题记录方式

每个问题尽量记录：

- 页码；
- 区域；
- 严重程度；
- 观察到什么；
- 为什么影响理解；
- 建议如何修改。

例如：

```text
P6 / 右下角图例 / major
图例在正常显示尺寸下不可读，观众无法区分三条曲线。
建议拆出当前子图并放大，而不是继续缩正文。
```

## 5. review-log.json

示例结构：

```json
{
  "reviews": [
    {
      "stage": "slides",
      "reviewer": "实际模型或工具名称；self-review 或 independent",
      "call_ref": "可定位的调用/会话引用",
      "inputs": [
        {
          "path": "renders/r02/slide-6.png",
          "sha256": "实际文件 SHA256"
        }
      ],
      "observation": "实际观察结果",
      "decision": "revise",
      "issues": [
        "P6 右下角图例过小，拆子图并放大后复审"
      ]
    }
  ]
}
```

`decision` 取：

- `pass`
- `revise`
- `blocked`

不要覆盖失败历史；每轮追加记录。`check_review.py` 按记录顺序取每个阶段的**最后一条**作为当前结论，所以只能在末尾追加，不要调整已有记录的顺序。

`check_review.py` 只能确认记录前后一致，无法确认 G2 / G3 真的问过用户。用户确认要在 `interview-log.md` 里引用用户的原话；测试或演示时没有真实用户，就标 `[SIMULATED]`，不能写成“已确认”。

通过记录不应仍包含未解决 issue。

`observation` 应包含事实、可读性、构图和整套节奏中适用的判断；不能只写“无溢出，pass”。图片变形、关键图例不可读、数量不一致或证据混用都属于必须修复的问题。记录工具 / 模型的实际调用引用；没有可复核记录时，不用汇总表的“全部通过”代替审阅证据。

## 6. 版本失效

内容、图片或布局改变后，旧页面的视觉结论失效。

原则：

- 改一页 → 重新渲染该页，并检查受影响邻页；
- 改字体/主题/页码等全局项 → 重新渲染全部受影响页面；
- 最终交付 → 每页通过记录必须对应当前图片哈希；
- 整套结论 → 必须对应最终 contact sheet。

`bridge.py render` 会生成 `render.json`；`check_review.py` 可以检查记录与当前文件版本是否一致。

**它只检查记录一致性，不调用视觉模型，也不判断美观或论文事实。**

## 7. 失败与阻塞

没有图像输入能力：

```text
blocked_visual
```

可以继续做内容草案，但不能宣称视觉通过。

连续多轮小修仍没有改善时，停止移动几个像素，改表达方式：

- 拆页；
- 放大局部；
- 删次要信息；
- 重画机制；
- 调整阅读顺序。

仍然不合格就如实保留未通过状态。

## 8. 敷衍页红线（2026-10 起）

以下任一条成立，直接判为不通过，不能靠微调位置补救：

- 页面只有一行字，却不是极简风格，或图占画面不到 70%；
- 结论 / 结果页没有证据（图、表、数字）或没有出处；
- 多子图的论文原图被整张缩小放入，里面的关键文字投影后读不清，且没有拆页、裁局部或重绘；
- 标注写了图里看不到、论文也没说的内容；
- 风格只换了配色，没有用该风格自己的招牌版式；
- 论点依赖图中小字（agent 输出、日志、代码），却没有重排为可读文字，只贴原图；
- 视觉审阅时所用的字体，既不是该风格指定的字体，也不是 `design-brief.md` 里已记录的替换字体（渲染器静默回退到默认字体）。

图表加工的参考实现见 `lab/annotated-v2/`（拆图、圈注、编号、压暗、重绘通信图与柱状图）。
