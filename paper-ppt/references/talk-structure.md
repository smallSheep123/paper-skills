# 讲述结构：先把研究讲通，再决定页面

论文汇报不是“把 paper section 逐页压缩”，而是让听众沿一条清楚的逻辑线理解研究。

## 1. 先写一条因果主线

推荐从这条链开始：

```text
为什么值得研究
→ 现有方法卡在哪里
→ 作者发现了什么关键现象
→ 方法如何利用这个观察
→ 哪些实验支持这个结论
→ 在什么条件下仍有限制
```

如果这条链讲不通，不要急着做 PPT。

背景只保留后面理解方法所必需的信息。一个具体例子通常比五页背景更有效。

## 2. 根据听众和时长调整深度

下面只是起点，不是固定页数。

| 场景 | 建议重点 | 深度 |
| --- | --- | --- |
| 8 分钟课堂 | 问题 → 核心 idea → 主要结果 | 讲清一个关键机制，其余放备份 |
| 15 分钟组会 | 背景约 20%，方法约 45%，实验约 25%，讨论约 10% | 加关键假设、消融、实现和自己的评价 |
| 更长精读 | 根据论文重新分配 | 可加入推导、失败案例、方法对比和下一步实验 |

课堂综述不要擅自变成研究提案；组会可以加入“我的理解”，但必须和作者结论明确区分。

## 3. 每页先回答两个问题

在设计页面前先写：

1. **这页在回答什么问题？**
2. **听完这页，观众应该记住什么？**

如果两者说不清，这页大概率还没有存在的必要。

然后再确定：

- 证据：Figure / Table / 章节 / 页码；
- 条件：baseline、数据集、指标方向、限制；
- 视觉焦点：这一页先看哪里；
- 阅读顺序：第二眼看哪里；
- 不放的内容：主动删什么；
- 过渡：怎么进入下一页。

## 4. 标题优先表达信息

弱标题：

- 研究背景
- 方法
- 实验结果

更好的标题：

- 生命周期分布漂移使静态分组快速失效
- 在线放置只能减缓债务，无法修复历史错误
- 在低迁移预算下，混合策略仍显著减少 stranded machines

结论型标题必须有证据。用户要求严格对应论文章节时，可以保留章节标题，再通过副标题或页内结论补足 message。

## 5. 方法页要讲机制，不是列模块名

至少让听众知道：

- 输入是什么；
- 核心状态/信号是什么；
- 哪一步真正改变了旧方法；
- 数据或控制流怎么走；
- 输出是什么；
- 为什么这能解决前面的具体问题。

复杂架构可以“总览 → 聚焦 → 机制”连续讲，不必一页塞完。

## 6. 实验页要说明“证明了什么”

不要只展示曲线。

每个主实验至少讲清：

- 比较对象是谁；
- 指标是什么，越高/越低哪个更好；
- 条件是什么；
- 图中最关键的变化；
- 这项结果支持哪条方法主张；
- 这项结果没有证明什么。

如果图太密，拆图、裁图、放大局部；不要缩到看不清。

## 7. 演讲备注

备注写“讲什么”，不是把页面文字再念一遍。

复杂 Figure 推荐顺序：

```text
先告诉观众看哪里
→ 再解释发生了什么
→ 最后说为什么重要
```

数字必须带比较对象和条件。页面上的克制不能靠口播夸大补回来。

备注时长只是估计；只有实际朗读/演练后，才能更可靠地校准总时长。

## 8. 组会额外准备

如果是研究组会，建议准备三件事：

- 最关键、也最脆弱的假设；
- 最有说服力和最不足的一项证据；
- 一个可以继续验证的具体小实验。

这些可以进结尾或备份页，但要标明是“汇报者判断 / 待验证”，不要伪装成论文结论。
