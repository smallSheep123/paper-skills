# 默认汇报结构（用户没给规划时用；给了就照用户的办）

8 分钟 / 9 页含封面的基准结构。要点：**方法占 3 页、背景 3 页、实验与总结 2 页**，
不要变成"背景五分钟、方法一分钟"。

| 页 | 内容 | 时间 | 页面形态 |
| --- | --- | --- | --- |
| 1 | 封面：系统名大字 + 全称 + 会议 + 作者/机构 + 报告人留空 | 0:20 | 深色大留白，不放关键词/一句话概括/贡献卡片 |
| 2 | 研究背景：让没读过论文的人懂"为什么值得做" | 0:50 | 自绘示意图 40% + 论文数据图 60%，底部一条结论带 |
| 3 | 生产/真实环境中的核心问题（Motivation 最重的一页） | 1:05 | 上下两层或两栏，自绘对比示意 + 论文图 |
| 4 | 现有方法为何不足 | 0:50 | 论文对比图 + 两三段短评，收在一个问题句上 |
| 5 | 系统总体设计（最重要结构页） | 1:00 | 论文架构图尽量放大 + 编号注释行（不做成 4 个卡片） |
| 6-7 | 方法关键组件逐个展开 | 各 1:00-1:05 | 自绘流程/Before-After + 论文消融图，混搭避免全是截图 |
| 8 | 实验结果（+ 生产部署若论文有） | 1:10 | 一张主图 + 两个辅助结果，大数字强调；**别四宫格、别塞 4 张图** |
| 9 | 局限（3 点）+ 结论链条 | 0:40 | 左右 55/45，右侧"问题→方法→结果"三框链条 + 一句收束 |

## 页面文字规则

- 页标题：短、正式、纯中文或纯英文（不混排）。可用：研究背景 / 研究动机 / 现有方法 / 系统设计 / 评估 / 局限与结论。
- 页面只放提纲式短语和关键数字；"作者为什么……"全部进演讲稿。
- 每页一个视觉焦点；底部问题句/结论带（浅色 tint 通栏）是好用的收束。
- 副标题槽可以放"看图方法"式的口头引导（如：只看四个模块——A · B · C · D）。

## 演讲备注（addNotes）规则

- 正式口语，不写"我们可以看到""接下来欢迎大家"这类水词；句尾标"（约 X 秒 / X 分 X 秒）"。
- 每页备注 = 这一页要说的话，全篇加总 ≈ 目标时长（8 分钟约 1100–1300 字）。
- 图复杂的页，第一句先给读图方法（"这张图不用看所有箭头，只看……"）。
- 技术细节属于论文不属于汇报：8 分钟讲不清的（公式推导、训练细节、内部参数）不上页面也不进主线备注。
