# 页面内容指南：每一页该放什么

> 从 105 套真实学术 deck（[风格图谱](slide-style-atlas.md)）蒸馏出的**内容层**规则：
> 不同场景该有哪些页、每页必须回答什么问题、放什么证据、文字预算多少、常见翻车点。
> 视觉怎么画看 [style-guide.md](style-guide.md) 和各风格 `STYLE.md`；讲述主线看 [talk-structure.md](talk-structure.md)。
> 这里的页序是**起点**，AI 要按论文和用户访谈结果删改，并把改动理由写进 `storyboard.md`。

---

## 0. 从 105 套 deck 里读出来的规律

| 场景（样本数） | 中位页数 | 中位词/页 | 篇幅比例：动机 / 方法 / 结果 |
|---|---:|---:|---|
| 会议 talk（20） | 38 | 36 | 35 / 40 / 25 |
| 主题报告 keynote（16） | 56 | 49 | 35 / 55 / 15 |
| 教程 tutorial（14） | 136 | 44 | 22 / 58 / 20 |
| 课程 lecture（20） | 51 | 48 | 12 / 78 / 10 |
| 答辩 defense（20） | 79 | 46 | 20 / 42 / 38 |
| 工作报告 / 组会（7） | 27–28 | 48 | 40 / 40 / 20 |

页数含动画分步导出的 PDF 页，实际“讲的页”通常是其一半左右。比例只统计了文中写明百分比的 deck，作趋势参考。

**评分最高的 deck 共有的 7 个内容习惯**

1. **标题是结论**，不是话题：“同等算力下精度 +4.4 pp”，而不是“实验结果”。
2. **一页一个意思**：评分 5 的 deck 中位 38 词/页，评分 ≤3 的是 51 词/页。多出来的字几乎都是“把论文段落搬上来”。
3. **一张主图贯穿全场**：系统图 / 框架图在后续页反复出现，只高亮当前讲的部分，而不是每页换新图。
4. **“This work” 页**：在动机之后用 1 页把贡献说完（2–3 条），结尾页回扣同一组贡献。
5. **问题驱动**：方法部分按“问题 → 洞察 → 设计”展开，每个组件前先说它解决什么。
6. **结果页先说结论再给图**：标出“越低越好 ↓”、基线、关键数字，读图负担交给讲者而不是听众。
7. **结尾不是“谢谢”**：最后一页是 takeaway / 局限 / 讨论问题，“谢谢 + Q&A”可以合在同页。

**常见扣分点**：目录页列 8 条以上；相关工作做成文献清单；一页塞 2 张以上原图且都看不清；实验页只贴表不说结论；整页复制论文摘要；结尾只有一页“Thanks”。

## 1. 按场景的页序模板

每行一页。“必需”页不建议删；“可选”页按时长和访谈结果取舍。页数以**讲的页**计（不含动画分步）。

### 1.1 组会读论文（读别人的论文，15–20 分钟，约 12–20 页）

最常用。核心是**让组里人在 15 分钟内知道这篇值不值得读、能不能借鉴**。

| # | 页 | 必需 | 这页回答什么 |
|---|---|:-:|---|
| 1 | 封面 | ✓ | 论文标题（原文）+ 中文意译、会议/年份、作者单位、汇报人、日期 |
| 2 | 一页看懂 Paper-at-a-glance | ✓ | 目标 / 难点 / 方法一句话 / 主结果一个数，配总览图 |
| 3 | 提纲 | 可选 | ≤5 项；10 页以内可省 |
| 4 | 背景 | ✓ | 这个领域在做什么，听众需要的最少前置知识 |
| 5 | 问题与动机 | ✓ | 现有方法哪里不行，最好有论文里的观察数据或失败例子 |
| 6 | 相关工作对比 | 可选 | 2–3 类方法 × 关键维度的小表，标出本文位置；不是文献清单 |
| 7 | 核心思路 / 贡献 | ✓ | 2–3 条贡献，各一句；这页是全场的“锚” |
| 8 | 方法总览 | ✓ | 框架图 + 数据流，说清输入、输出、新模块在哪 |
| 9–11 | 方法细节（每个关键模块 1 页） | ✓ | 这个模块解决什么问题 → 怎么做 → 为什么有效；公式只留 1 个核心式 |
| 12 | 实验设置 | ✓ | 数据集、基线、指标、硬件；一句“公平性”说明 |
| 13 | 主结果 | ✓ | 标题写结论，标出最关键的一个数和比较条件 |
| 14 | 消融 / 分析 | ✓（详细版） | 哪个组件贡献最大，证明了哪条贡献 |
| 15 | 案例 / 可视化 | 可选 | 定性例子，选论文里最有说服力的 |
| 16 | 局限与我的看法 | ✓ | 论文自述局限 + 汇报人观察（标明是个人观点） |
| 17 | 对我们组的启发 | ✓ | 能借鉴什么、能不能复现、和组里课题的关系 |
| 18 | 总结 + 讨论问题 | ✓ | 3 条结论 + 2–3 个开放问题，可兼 Q&A |
| — | 备份页 | 可选 | 额外实验、证明细节、超参，放在结尾之后 |

**简略版（约 10 页）**：保留 1、2、5、7、8、9（合并为 1–2 页）、13、16+17 合并、18。

### 1.2 会议 talk / 讲自己的论文（12–20 分钟，约 15–25 页）

听众不读论文，只记得 1 个洞察和 1 个数字。篇幅约 **35% 动机 / 40% 方法 / 25% 结果**。

| # | 页 | 必需 | 这页回答什么 |
|---|---|:-:|---|
| 1 | 封面 | ✓ | 标题、作者（可带头像）、单位 Logo、会议 |
| 2 | 场景引入 | ✓ | 一个具体的应用或数字，让外行也知道为什么重要 |
| 3 | 问题 | ✓ | 一句话定义问题，配一张示意图 |
| 4 | 现有方法为什么不够 | ✓ | 2–3 类方法各自的根本局限，可用“暗化 + 局限框”逐个讲 |
| 5 | 关键观察 / 洞察 | ✓ | 测量数据或例子支撑的一个反直觉事实，全场最该记住的一页 |
| 6 | This work | ✓ | 2–3 条贡献；后面的方法和实验都回扣这页 |
| 7 | 系统 / 方法总览 | ✓ | 主图首次完整出现 |
| 8–12 | 设计要点 #1…#3 | ✓ | 每个要点：挑战 → 设计 → 为什么对，主图高亮对应部分 |
| 13 | 实现 | 可选 | 代码量、部署规模、开源地址 |
| 14 | 实验设置 | ✓ | 一页说完，不逐条念 |
| 15–17 | 关键结果（每页一个问题） | ✓ | “比基线快多少”“扩展性”“开销” 各一页，标题即答案 |
| 18 | 结论 | ✓ | 回扣 This work 的贡献，加开源链接 / 二维码 |
| — | 备份页 | ✓ | 预判 Q&A 的 3–5 个问题各准备 1 页 |

### 1.3 学位答辩（硕士 20–30 分钟 / 博士 40–45 分钟）

评委关心：**工作量、创新点、每章之间的逻辑、是否独立完成**。结果占比明显更高（约 38%）。

| # | 页 | 必需 | 这页回答什么 |
|---|---|:-:|---|
| 1 | 封面 | ✓ | 论文题目、答辩人、学号、导师、学院、日期、校徽 |
| 2 | 提纲 | ✓ | 与论文章节对应，后续每章前回显并高亮当前章 |
| 3 | 研究背景与意义 | ✓ | 国家需求 / 应用价值 + 学术意义各一段 |
| 4 | 国内外研究现状 | ✓ | 按技术路线分类的对比表或时间线，最后一行指出“尚未解决的问题” |
| 5 | 研究问题与总体框架 | ✓ | 一张总框架图：几个研究内容、各自对应哪章、之间的关系 |
| 6 | 主要贡献 / 创新点 | ✓ | 3–4 条，每条对应一章 |
| 7… | 每章：问题 → 方法 → 实验 → 小结 | ✓ | 每章 3–6 页；章末 1 页“本章小结”回扣创新点 |
| — | 系统 / 应用验证 | 可选 | 工程类论文的平台或部署 |
| n−3 | 总结 | ✓ | 回扣创新点，每条一句结论 + 一个关键数字 |
| n−2 | 不足与展望 | ✓ | 2–3 条，诚实具体 |
| n−1 | 攻读学位期间成果 | ✓ | 论文（标注作者位次、期刊/会议等级）、专利、项目 |
| n | 致谢 | ✓ | 可与“恳请各位老师批评指正”同页 |
| — | 备份页 | ✓ | 评委常问：数据来源、与某方法对比、参数敏感性、复杂度 |

**开题 / 中期**：在答辩页序基础上把“每章”换成“研究内容 1/2/3 + 技术路线 + 预期成果 + 进度安排 + 已有基础”；中期加“已完成 / 未完成 / 调整说明”。

### 1.4 课程讲授 / 教程（按课时）

方法占比最高（约 75%），靠**例子驱动**。

页序：封面 → 本节目标（3 条“学完能做到”）→ 回顾上节 → 动机例子 → 概念 1（定义 → 直觉图 → 例子 → 小测）→ 概念 2 … → 完整例题走一遍 → 常见误区 → 本节小结 → 作业 / 延伸阅读。
教程每 30–45 分钟放一页“休息 / 小结”，长教程每部分开头回显总议程（带分钟数）。

### 1.5 工作汇报 / 项目进展 / 基金汇报（10–15 分钟）

页序：封面 → 一页结论（上次以来最重要的 1–3 件事）→ 目标与计划回顾 → 进展（每项：做了什么、结果、和计划比）→ 问题与风险 → 下一步计划（带时间）→ 需要的支持 / 讨论。
标题全部写结论；“正在做”的事说清楚预计完成时间。

### 1.6 主题报告 / 综述 / Job talk（30–60 分钟）

页序：封面 → 一个大问题 / 愿景 → 总体框架（作为全场导航，反复回显）→ 2–4 个部分，每部分是“一个发现 + 支撑工作” → 综合 / 交叉观点 → 未来方向 → 总结。
Job talk 额外要：个人研究脉络一页、未来 3–5 年计划一页、与招聘单位方向的结合。

## 2. 每类页面的内容契约

AI 生成每一页前对照本表：**必须有**的缺一项就补，**不要**的出现就删。文字预算按 16:9、正文 18–20 pt 计；中文按字、英文按词。

### 封面

- 必须有：标题（原文）、作者与单位、会议/期刊与年份、汇报人、日期；中文场景加中文意译或副标题。
- 可选：一张代表图、二维码、组会名称。
- 不要：摘要、贡献列表、大段背景。
- 读别人的论文时，**汇报人与论文作者分开写**，避免被误认为作者。

### 提纲 / 导航

- ≤5 项，每项 ≤10 字 / 5 词；后续章节页回显并高亮当前项。
- 10 页以内的短汇报可省略，改用一页看懂。

### 一页看懂（Paper-at-a-glance）

- 必须有：目标、难点、方法一句话、主结果一个数，配论文总览图。
- 预算：4 个字段各 ≤25 字 / 15 词。
- 这页单独拿出去也应该能让人知道论文做了什么。

### 背景

- 只讲听众理解后文**必需**的概念；每个术语第一次出现时给一句白话解释。
- 用一张示意图代替 3 段文字。
- 不要：领域发展史、与本文无关的大综述。

### 问题与动机

- 必须有：具体的失败例子、测量数据或成本数字（论文图表或原文），并给出处。
- 标题写“现有方法在 X 下损失 Y%”，而不是“研究动机”。
- 预算：≤3 条要点，每条 ≤28 字 / 15 词。

### 相关工作

- 形式：分类对比表（行 = 方法类别，列 = 关键能力 ✓/✗）或二维定位图，标出本文位置。
- 每类方法写**根本局限**，不是逐篇罗列。
- 读论文场景可省，或并入动机页。

### 洞察 / 关键观察

- 一个反直觉的事实 + 支撑它的数据或例子；全场最该被记住的一页。
- 版面：大字陈述 + 一张图或一个大数字。

### 贡献 / This work

- 2–3 条，每条一句、动词开头（“提出…”“证明…”“开源…”）。
- 后续方法和实验页要能一一回扣；结尾页再次出现。

### 方法总览

- 必须有：框架图（优先论文原图，必要时重绘简化版）、输入 → 输出的数据流、新模块高亮。
- 图占版面 ≥50%；文字 ≤3 条，解释图里看不出的东西。
- 后续细节页复用这张图，只高亮当前模块。

### 方法细节（每模块一页）

- 结构：**它解决什么问题 → 怎么做 → 为什么有效**。
- 公式：只放 1 个核心式，逐项标注符号含义；推导放备份页。
- 算法：伪代码 ≤8 行，高亮关键一行。
- 不要：模块名清单、超参数表、把论文 Method 段落分点照抄。

### 实验设置

- 一页说完：数据集（规模）、基线（为什么选它们）、指标（越高/越低越好）、硬件与训练预算。
- 一句话说明比较是否公平（同数据、同算力、种子数）。

### 主结果

- 标题 = 结论 + 关键数字（“同算力下精度 +4.4 pp”）。
- 必须有：原图或重绘图、基线标注、方向提示（↑/↓）、比较条件、出处（Table/Fig 编号）。
- 一页只证明一件事；多张表拆成多页或只留最关键的一列。
- 数字必须能在论文原文找到；论文没给的不要推算。

### 消融 / 分析

- 回答“哪个设计最重要”，并明确对应第几条贡献。
- 用横向条形图或小表，突出去掉后掉得最多的那一项。

### 案例 / 可视化

- 选 1–2 个最能说明机制的例子，标出看哪里（箭头、框）。
- 可选失败案例，诚实讲边界。

### 局限与讨论

- 论文自述局限 + 汇报人的观察；两者分开标注。
- 读论文场景加“对我们的启发 / 能否复现”。

### 总结

- 3 条结论，各一句；回扣贡献页。
- 可附开源链接、二维码、联系方式。

### 讨论问题 / Q&A

- 组会给 2–3 个具体可讨论的问题，而不是只写“Q&A”。
- “谢谢”可以和总结或讨论页合并。

### 备份页

- 放在结束页之后，标题加“Backup / 备用”。
- 优先准备：被问概率高的实验、证明细节、超参与复杂度、与某个具体方法的对比。

## 3. 演讲备注（每页）

- 第一句：这页的结论（与标题一致）。
- 中间：讲图的顺序（先看哪里、再看哪里），以及图里看不出的关键信息。
- 最后一句：过渡到下一页的问题。
- 时长参考：内容页 40–70 秒；封面、提纲、章节页 10–20 秒。总时长超出时优先把细节移进备份页，而不是加快语速。
- 备注里出现的数字同样要能追溯到论文。

## 4. 生成前的自检清单

- [ ] 页序与场景匹配，删改理由写进 `storyboard.md`
- [ ] 每页标题都是一句结论
- [ ] 贡献页存在，且结尾回扣
- [ ] 主图被复用，而不是每页换新图
- [ ] 每个数字都有论文出处（页码 / 图 / 表）
- [ ] 单页文字未超预算；超出的移到备注或备份页
- [ ] 结尾有 takeaway 或讨论问题，不是只有“谢谢”
- [ ] 讲的页数 × 平均每页时长 ≈ 用户给的时长
