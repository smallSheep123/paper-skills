# 详略档位与内容充足性自检

两件事都发生在 Design 之前：先定**讲多细**，再判断**素材够不够讲这么细**。

## 1. 详略档位

用户没给时长、页数或“详细/简略”时，开工前问一次（问法见 SKILL.md §0）。用户给了时长就按下表推断，不再问。

| 档位 | 时长 | 主线页数 | 内容范围 | 备份页 |
| --- | --- | --- | --- | --- |
| **简略** | 8–10 分钟 | 8–12 | 问题 → 核心思路 → 1 页方法 → 1–2 个关键结果 → 结论；测量细节、消融、相关工作基本不讲 | 0–3 页，放被问到概率最高的图 |
| **详细**（默认） | 15–20 分钟 | 16–22 | 背景与动机、测量/观察、方法拆解、主要实验、消融或对比、局限与讨论 | 3–6 页 |
| **精读** | 30 分钟以上 | 22–30 | 每个主要图表、附录关键结果、实现细节、与相关工作的逐项对比、复现与延伸 | 不限，按章节分组 |

规则：

- 档位决定**讲什么**，不决定字号和密度；简略版不是把详细版每页塞得更满；
- 用户只说“组会”时按详细版；说“快速过一下 / 讲个大概”按简略；说“精读 / 逐段讲”按精读；
- 选定档位、推断依据写进 `design-brief.md` 的“未指定条件与采用的默认假设”。

## 2. 内容充足性自检

AI 在 Source 阶段结束时自己做，不需要用户参与。每一项给出 **够 / 不够 / 不适用**，并写入 `source-notes.md` 末尾。

### 2.1 图表覆盖

- [ ] 有完整图表清单（`pdf_snap.py inventory` 初稿 + 看图修正），编号连续、无遗漏，附录图表也在内；
- [ ] 计划进入主线的每张图都**实际看过页面截图**，并裁切、打开核对过（坐标轴、图例、子图编号完整）；
- [ ] 每张入选图写清“它能支持什么结论、不能支持什么结论”。

### 2.2 数字可溯源

- [ ] 计划上页面的每个数字都能指到 页码 + 图/表/段落；
- [ ] 文本层与图上读数不一致时，以图为准并记录；正文前后口径不一致时（如引言 vs. 实验节），两处都记下，页面采用实验节数据，并在备注中说明；
- [ ] 区分原文结论 / 可核验计算 / 汇报者解释 / 延伸设想。

### 2.3 主线完整

- [ ] 摘要/引言的每条贡献或主张，都至少有一张图、一张表或一段实验对应；
- [ ] 方法能用 1–3 页讲通：输入、关键机制、输出、为什么有效；讲不通说明素材或理解不足，回去读；
- [ ] 当前档位需要的部分都有素材（例如详细版需要消融/对比，精读需要附录）。

### 2.4 文本层可信度

- [ ] 抽查 2–3 处多栏、图注、表格、公式附近的文本，与截图对照；错乱明显时，这些区域一律以截图为准；
- [ ] 公式：进入页面的公式来自原图裁切，或由视觉模型对照截图转写并标注；
- [ ] 上下标和指数：文本层常把 `100²` 抽成 `1002`、把 `10^-3` 抽成 `10-3`，所有带上下标的数字都要对照截图核对；
- [ ] 图表清单：`pdf_snap.py inventory` 结果是 0 条，或数量明显偏少（图注格式特殊、Algorithm 没有图注行）时，对照页面截图手工补齐；
- [ ] 扫描件、文本层缺失、大量公式/表格需结构化 → 建议叠加 MinerU 路径。

### 2.5 不够时怎么办

| 情况 | 处理 |
| --- | --- |
| 图看不清、裁切不全 | 提高 dpi 重新 `crop`，或改用整页截图局部放大 |
| 论文本身没给（细节在附录/补充材料/代码） | 找附录、补充材料、项目主页、代码仓库；找到的写明来源 |
| 外部也找不到 | 记为“未确认”，页面不放该数字，或改为定性表述 |
| 需要用户判断（汇报重点、听众背景、组里关心的问题） | 合并成一个问题问用户，最多一次 |
| 原生路径整体不可靠 | 建议用户启用 MinerU 路径，或两者并行 |
